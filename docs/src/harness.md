# Agent harness: roles and delegation

Read this before changing any delegation, brief or routing rule (`nix/home/configs/claude/CLAUDE.md`, `nix/home/configs/.agents/AGENTS.md`, `nix/home/configs/claude/hooks/architect-rules.py`, [model routing](./model-routing.md)). Every such rule serves the role model below; a rule that contradicts it is the rule's bug.

## The role model

The user stated it on 2026-11-27:

> 사용자가 CTO 임원급으로 방향과 큰 설계를 전달해. 그럼 Opus가 핵심 설계자로서 DDD, 작업 분할, 구현 아이디어 체크 등 실무자로서 오케스트레이션을 해. 그리고 C-lv user와의 소통을 놓치지 않기 위해 worker는 값싸게 위임해. 신입급으로. 그에 준하게 지시를 세세히 내리고, 강하게 마이크로매니징해.

- The user is the CTO. They give direction and the large design.
- The main Opus session is the lead practitioner. It owns domain design (DDD), splits the work, checks implementation ideas and orchestrates. It owns every worker's outcome.
- Workers are cheap junior hires. Main delegates to them so its own thread stays free for the user. A junior gets a detailed brief and close supervision, and reports to main whenever an instruction is ambiguous or something fails (triggers in P7).

Autonomy is deliberate: "가드레일이 너무 빡빡하면 될 작업도 안되니까" (guardrails that are too tight block work that would otherwise succeed). A fix for an agent's bad judgment changes the orchestrator's briefs and decisions; agents keep their current permissions. A last-resort safety net that fires only when the machine is about to die stays: `resource-watchdog.py` (`nix/home/configs/claude/resource-watchdog.py`), which freezes the biggest agent job under memory pressure.

## Where the current rules drift from it

Found 2026-11-27, after the Mac's hardware watchdog (iBoot) reset the machine (see [agent incidents](./agent-incidents.md)).

1. `architect-rules.py` justifies delegation by cost ("the main model's own tokens are the expensive ones"). The reasons in the role model, keeping main free for the user and main owning the outcome, are absent.
2. The Claude worker brief (`CLAUDE.md`, "A delegated unit gets one BACKGROUND worker with a brief carrying goal, files and a `Skills:` line ... not thread history") has no slot for observed failures, refuted premises or stop conditions. "not thread history" reads as "drop the failure record". The codex brief in `architect-rules.py` is richer (`Preserve:`, `Baseline:`, `Done when:`).
3. `AGENTS.md` "Re-verify a Claude worker's report only when it lacks commands and output, or the change reaches past what it checked" trusts a worker by default, the opposite of close supervision.
4. Tier routing ("`sonnet` well-scoped, `opus` deep" in `architect-rules.py`; "opus does hard cross-cutting implementation" in [model routing](./model-routing.md)) raises the worker's tier for hard work. In the role model, main's brief and decisions absorb hard work.
5. No rule names the points where main must decide before the next dispatch.
6. A worker reports only at the end. No rule makes it report an ambiguity or failure while it works.
7. Main cannot see which worker started which process, and stopping a worker may leave a job it detached running.
9. Review hooks decide by path, not by reader or lifetime. `prose-review-nudge.py` orders "spawn the `prose-editor` subagent" for every `.md`/`.html` outside agents, skills and memory, so a one-line `SUMMARY.md` entry and a long-lived doc get the same order. The agent can only obey it everywhere or skip it everywhere.
8. `AGENTS.md` routes durable narratives to `memory/evidence/` ("One file under `memory/evidence/` per non-obvious conclusion ... skill `evidence-store`"; repo `AGENTS.md`: "write the narrative into `memory/evidence/` or `docs/src/agent-incidents.md`"). Agents write there and rarely read it back.

## Improvement plan

Proposed 2026-11-27; checked items applied the same day. P10 kept the hooks that guard against an irreversible or machine-wide loss (apology-leak, baseline-lock, claude-dir-edit, declarative-package, flake-stage, git-integrity, git-push, gui-launch, leak, nsc, publish, slack-subagent, ssh) and the non-guard hooks (architect-rules, mcp-auth-log, rex-project-theme), and removed the other 20. P8 (`0663f69`, reworked 2026-11-27): the resources mod attributes every process a worker's Bash call starts to that worker, so pressure and watchdog notes say `started by worker <id>` and a successful `TaskStop` kills what the worker left running (SIGTERM, then SIGKILL after 3 s). Before this, a subagent's env matched main's, and a `(nohup sleep 1777 &)` survived `TaskStop` with ppid 1 (measured 2026-11-27). The first mechanism exported `CLAUDE_AGENT_ID=<agent id>;` in front of every worker command, which turned every worker call into an approval ask (in auto mode, approving every command by hand), and a `tool.check` re-check of the untagged command did not stop it; both are removed, and the Bash hook now passes the command through byte-identical. What works now: Claude Code runs each Bash call as a child of the claude process, `zsh -c "source <snapshot> ... && eval '<command>' < /dev/null && ..."`, and that shell leads its own process group (pgid = shell pid) which a detached job keeps after the shell exits (measured 2026-11-27: shell 48496 -> orphan `sleep` ppid 1 pgid 48496). `hooks/fork-tracker.py`, started once per claude pid at `session.start` through `$.process.spawn` (flock-guarded, exits with claude), waits on kqueue `NOTE_FORK` of the claude pid and appends `{pid, pgid, argv, t}` for each shell to `~/.local/state/claude/resources/forks/<claude pid>.jsonl` while the shell still runs (40 of 40 trivial fast calls recorded; a `(nohup sleep 41 &)` call was recorded about 80 ms after the hook saw it). When a Bash call settles, the hook matches it to the ledger line whose argv holds `eval '<command>'` (each `'` written `'"'"'`) with a time inside the call's window, in start order when two identical commands are in flight, and stores pgid -> agent id in the session's resource state (`agentPgids`); a pgid no process carries is dropped. `TaskStop` first matches calls still in flight, then kills every live process whose pgid maps to the stopped worker. Residuals: a command rewritten by a hook below the resources mod does not match its ledger line and stays unattributed (logged); a job that makes itself a new process group (`setsid`) leaves the worker's group; the watchdog still reads `CLAUDE_AGENT_ID` from env (never set now), so the mod resolves the worker from the stopped pid's pgid when it builds the notice.

- [x] **P12** Workers are short-lived and start warm. The user approved this design on 2026-11-28:
  - Every delegated unit goes to the `efficient-worker` template (`nix/home/configs/claude/agents/efficient-worker.md`) unless a more specific agent type fits. Its frontmatter: `omitClaudeMd: true`, `maxTurns: 150`, `autoCompactWindow: 100000`, `background: true`, `model: sonnet` (the caller's `model` param overrides it), tools unrestricted. `omitClaudeMd` also drops the project `AGENTS.md`/`CLAUDE.md`, so the body tells the worker to read the working repo's file before its first edit, and carries only the worker-side rules: follow the brief, the P7 report triggers, the short life below, UI surfaces behind the user's windows, stop what it started, commit only when briefed, done means the artifact ran.
  - A worker cannot live long. Once main accepts a unit, the next unit goes to a new worker with a new brief; the same worker receives only fix requests for its own unit. A worker that has compacted once sends a handoff report and stops, and main spawns a new worker from that report.
  - Cache warm-up for siblings: spawn worker a first, and only when a's `outputFile` or transcript shows its first assistant response, spawn a2..aN together, within 5 minutes (the prompt-cache TTL). Siblings share agent type and model, and their briefs put the shared part first, byte-identical, with the unit-specific part after it. Main waits on that condition, never on a clock.
  - A worker whose next step would wait on another task (another worker's result or another long-running task) sends a state report and ends instead of waiting; a reply from main at a `Stop when:` or checkpoint is still waited for (P7); when the wait is over, main spawns a new worker with that report as the brief. No tool lets a worker request its own compaction, which is why it ends instead.
  - Measured by main on 2026-11-28 from `~/.claude/projects/*/*.jsonl`: three sessions ran 7 h in parallel on 2026-11-27 13:08-20:30 UTC. Main threads read ~120M cached tokens; their 48 workers read ~316M, created 19.7M and output 4.0M, so workers were ~72% of reads. Every long worker sat near a 167k context.   - Worker startup context is ~26-28k tokens, about main's; `~/.claude/CLAUDE.md` alone is 26,828 bytes (~7k tokens) on every call, which `omitClaudeMd` removes.
  - Two same-type workers spawned in the same second (05:07:01 and 15:11:39 UTC) both had cache_read 0 and created 29k-47k each: concurrent spawns share no cache, because the cache is written only after the first request completes. Same-type workers spawned minutes apart read 11-23k from cache on their first call.
  - 87 worker calls re-created more than 50k of context (8.0M total), likely cache expiry after waits over 5 minutes (cause unverified).
